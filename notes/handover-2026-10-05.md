## Conceptual Milestone

The agreed architecture separates source-specific data preparation from harmonised analytical outputs.

Source environments differ:

- CHN QAR data is trajectory-like data enriched with fuel-burn information.
- EUROCONTROL/PRU fuel-burn data is processed internally and culminates in milestone and phase-summary tables.
- OSN/ADS-B data is trajectory-only and useful for algorithmic reference work, but it is not expected to be the main European fuel-burn input.

The reproducible contract should therefore be a set of harmonised outputs rather than a single raw-data pipeline:

- a canonical milestone table,
- derived level-segment tables,
- phase summaries,
- flight-level summaries,
- paper-specific indicators derived from those harmonised outputs.

The enriched milestone model is now documented in `notes/canonical-milestone-model.md` and recognised in `technical-note-data-preparation.qmd`. It adds analytical along-track distance anchors (`D040`, `D100`, `D200`, `A200`, `A100`, `A040`), pressure-altitude flight-level anchors (`D_FL075`, `D_FL100`, `D_FL180`, `A_FL180`, `A_FL100`, `A_FL075`), and paired level-segment boundaries (`LVL_START`, `LVL_END`).

## Level-Off Treatment

The current preference is to keep level-off detection and level-off qualification separate.

- Detection should produce generous candidate level-off start/end milestones.
- The milestone table should preserve the event vocabulary and segment ids where available.
- A derived level-segment table should reconstruct intervals from paired milestones.
- The paper should decide which level segments are considered material, using duration and possibly altitude-band or phase filters.

This keeps the PRU VFE definition available as a reference case without prematurely locking the paper to one duration threshold. Sensitivity across CHN and European data can then become part of the analysis.

## Next Iteration

Suggested next steps:

1. Audit existing PRU milestone labels and fields against the enriched convention, especially `D40`/`A40`, `D100`/`A100`, generic `FL100`, and `LVL`.
2. Define canonical renaming and derivation rules, including `D40` to `D040`, `A40` to `A040`, and direction-aware flight-level labels where the phase context supports them.
3. Confirm that `DIST_FLOWN_NM` and pressure-altitude fields support deriving the additional distance and flight-level milestones without rerunning heavy processing.
4. Add a local `R/level-off-milestones.R` that derives level-segment intervals from paired milestone events.
5. Run the level-segment derivation on the CHN canonical helper outputs and the European milestone sample to inspect segment-duration distributions.
6. Use those distributions to choose paper-level qualification thresholds and sensitivity scenarios.
