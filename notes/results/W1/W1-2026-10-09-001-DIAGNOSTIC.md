## Root Cause Analysis

### Issue 1: Alternating Pairing Assumption

**Location:** `R/eur-milestone-harmonization.R` lines 142-173

**Current logic:**
```r
lvl_events <- df |>
  dplyr::filter(.data[[mst_col]] == "LVL") |>
  dplyr::arrange(dplyr::across(dplyr::all_of(order_cols))) |>
  dplyr::group_by(.data[[uid_col]]) |>
  dplyr::mutate(
    .lvl_seq = dplyr::row_number(),
    .is_odd = .lvl_seq %% 2 == 1
  )

# Odd = START, Even = END
lvl_starts <- lvl_events |> dplyr::filter(.is_odd) ...
lvl_ends <- lvl_events |> dplyr::filter(!.is_odd) ...
```

**Problem:** This assumes LVL milestones always alternate perfectly between segment boundaries. If the raw PRU data has:
- Multiple consecutive level segments without explicit markers
- Implicit segment boundaries  
- Out-of-order markers
- Missing markers

Then odd/even pairing creates artificial segment keys that don't match source reality.

### Issue 2: Missing Source Segment IDs

**Raw PRU schema:** SAM_ID (segment ID from source), not UID  
**Current processing:** Loses SAM_ID → flight mapping, creates synthetic segment_id

**Impact:** Cannot trace repeated keys back to source segments to validate pairing

### Issue 3: Missing Distance Recovery

**Raw PRU has:** `DISTANCE_NM` field per segment  
**Current processing:** Distance field not carried forward to processed level segments

### Issue 4: Phase Label Mismatch

**Script 07 (`07-enrich-eur-level-segments.R`):** Checks for uppercase `CLIMB`/`DESCENT`
**Delivered data:** Uses lowercase `Lvl_climb`/`Lvl_descent`
**Impact:** Altitude heuristic may dominate milestone-window context

## Proposed Fixes

### Fix 1: Source-ID-Based Reconstruction

**Approach:** Preserve SAM_ID from raw PRU data and use for pairing

```r
#' Reconstruct level segments using source segment IDs
#' 
#' Instead of alternating pairing, use actual segment IDs from source
#' to establish start/end boundaries.
reconstruct_level_segments_v2 <- function(
    df, 
    uid_col = "UID",
    sam_id_col = "SAM_ID", 
    mst_col = "MST",
    order_cols = c("UID", "TIME")
) {
  
  # For LVL events with SAM_ID, group consecutive events by segment
  lvl_with_id <- df |>
    dplyr::filter(.data[[mst_col]] == "LVL", !is.na(.data[[sam_id_col]])) |>
    dplyr::arrange(dplyr::across(dplyr::all_of(order_cols)))
  
  # Group by SAM_ID and take first/last event as START/END
  lvl_segments <- lvl_with_id |>
    dplyr::group_by(.data[[uid_col]], .data[[sam_id_col]]) |>
    dplyr::summarise(
      start_event = dplyr::first(.data),
      end_event = dplyr::last(.data),
      .groups = "drop"
    )
  
  # Create START markers
  lvl_starts <- lvl_segments$start_event |>
    dplyr::mutate(
      !!mst_col := "LVL_START",
      .milestone_source = "source_sam_id_start"
    )
  
  # Create END markers (only if different from START)
  lvl_ends <- lvl_segments |>
    dplyr::filter(start_event != end_event) |>
    dplyr::pull(end_event) |>
    dplyr::mutate(
      !!mst_col := "LVL_END",
      .milestone_source = "source_sam_id_end"
    )
  
  # Fall back to alternating pairing only for events without SAM_ID
  lvl_no_id <- df |>
    dplyr::filter(.data[[mst_col]] == "LVL", is.na(.data[[sam_id_col]]))
  
  # Combine
  dplyr::bind_rows(lvl_starts, lvl_ends, 
                   reconstruct_level_segments_legacy(lvl_no_id, ...))
}
```
